# Mobile Build — Grilling Interview Record

> Living doc for the ongoing `/grilling` + `/domain-modeling` session on the **customer mobile app** (React Native / Expo). One question at a time; decisions captured the moment they crystalise. ADRs live in `docs/adr/`; the glossary lives in `CONTEXT.md`.

## Phase
Customer-first **React Native (Expo SDK 54) + TypeScript** delivery app. Flutter dropped (ADR-0001).

---

## Resolved decisions

| # | Area | Decision |
|---|------|----------|
| 1 | **Stack** | React Native (Expo SDK 54) + TypeScript; Flutter (`Flutter-GroceryApp-main`) dropped. `SNEAKSY`/`MOBILE_APP_UX` "native = Flutter" notes superseded by ADR-0001. |
| 2 | **`.opensrc`** | Adopt only `zustand` 5.0.14 + `react` 19.2.8; the ~43 other cached packages are web/DOM-focused and excluded. |
| 3 | **Typography** | Two-font system (ADR-0002): platform system sans = "Checkstar font" (weight 700–900, tight tracking) for all UI; **Caveat** script (`expo-font`, OFL) for orange-emphasis moments (discount %, sale price, "Special Offer", active pill). Type-scale structure: title/display 28–40 · brand 22–24 · heading 16–18 · body 14–15 · caption 12 · micro 9–11 uppercase+tracking · price value tabular. |
| 4 | **Logo** | One `Logo` component, `stacked` (icon above wordmark: splash/onboarding) + `lockup` (icon left + wordmark right: header/cart-empty/account) variants. Icon Star = `react-native-svg` (white wing + `#EB6522` orange check, from `checkstar-logo-icon-star.html`). Wordmark = real `<Text>` (orange **Check** + white **star**) + **cares enough** in Caveat. Hero-once animation (wing/check reassemble ~650ms) then quick 250ms fade; tracked in module. Theme-aware. |
| 5 | **Motion** | GreenBidder boosters (FadeSlideIn, TactilePressable, usePressAnimation, haptics, AnimatedLogo, AnimatedError/useErrorShake, FadeEdgeScroll, ScrollAwareCard, useOnboardingSlideMotion, SkeletonCard) + Sneaksy gap-fillers (angled product image rotate −12…−30°, 32px morph-drawer from tapped rect, collection pills, glass toast, `useColorScheme` light/dark). One motion-language token set: entrance `20/180`, press-in `18/450`, press-out `22/400`, exit ~60–70% faster; animate opacity+transform only. |
| 6 | **Onboarding** | 3 value-prop slides (`react-native-pager-view`) w/ staggered entrances (image→badge→title→subtitle) + parallax swipe; Stacked logo hero-once + Caveat on emphasised words. Slides: (1) fresh groceries delivered (Durban), (2) save on Specials, (3) track delivery live. Primary CTA **"Start shopping"** → Browse without auth (Guest); sign-in prompted at checkout. Secondary **"I'm a Rider"** → separate Rider registration (vehicle, banking, availability). **Show-once** gating (`react-native-mmkv`); Skip button. Returning users: Splash → Home (quick fade). |
| 7 | **Data source (A1)** | **Live Laravel/Sanctum API** for all browsing + flows. Public endpoints serve Guest browsing unauthenticated; session only required for placing Orders. Accept one-time cost: pin CORS + mobile base URL. |
| 8 | **Auth (A2)** | **Email + password** for Customer and Rider (drops phone→OTP — no infra exists). Backend extended **additively** to issue **Sanctum Personal Access Tokens** on register/login; mobile sends `Authorization: Bearer`; web cookie/SPA auth untouched. Token stored in **`expo-secure-store`** (not MMKV/AsyncStorage). Guest = public endpoints, no token; sign-in prompted at checkout. |
| 9 | **Delivery-Store & browse (A3)** | **Delivery-Store first** model: on first Home, `expo-location` picks nearest Store within `delivery_radius_km`; permission-decline → Store picker; Home header shows chosen Store + manual override; persisted. **Additive backend:** optional `?store_id=` on public `/products`(+categories/specials) scoping to `store_product` availability (excludes `is_available=false`/zero-stock); no-store_id behaves as today. Cart/checkout use chosen Store's `store_product_id`s. Accepted: dispatch may still fall back to a different Store (backend policy, unchanged); order timeline shows actual fulfilling Store. |
| 10 | **Cart (A4)** | **Guest cart is local** — zustand persisted to **`@react-native-async-storage/async-storage`** (72h+). On sign-in → **merge** through `/cart/sync`; server cart authoritative for signed-in. Additive backend: `/cart/sync` also writes the delivery Store's `store_product_id`. **Store-switch validation:** items unavailable at the new Store are flagged + removed with a confirm sheet, never silently. Cart badge reads from the zustand store. _(Persistence swap mmkv→async-storage for Expo Go, see 17b.)_ |
| 11 | **Tracking liveliness (A5)** | **Polling + local notifications** (no new server infra): poll `GET /orders/{id}` ~20s while active, **~10s during `out_for_delivery`**, stop on terminal. Live = status timeline updating in place (no map pin — no coordinate API this phase). `expo-notifications` local notifications on detected status changes. **Remote push (FCM) + rider-map deferred.** |
| 12 | **Payment (A6)** | **COD v1 + Stripe-prepared.** `payment_method` enum added on Orders (`cod`|`card`, default `cod`, set at intake). `PaymentStateMachine` unchanged — `paid` today fires on Delivery Confirmation (COD); with Stripe later it fires on charge success (same machine, different trigger). `transactions` table reserved for Stripe (`payment_intent` in metadata). App `checkout/` module has a **payment-method selector seam**: v1 shows only "Cash on delivery" (enabled); `card` disabled "coming soon". Refunds ops-only until Stripe lands. |
| 13 | **Server-state (B1)** | Add **`@tanstack/react-query` v5** (the one new dependency outside GreenBidder/opensrc). **TanStack Query = server-state** (caching, refetch-on-focus, mutations, `refetchInterval` polling for A5); **zustand = client-state** (cart draft, session/token, delivery-Store, onboarding flag). |
| 14 | **Scaffolding (B2)** | New **`mobile/`** folder at repo root, standalone Expo app (sibling to `backend/`/`frontend/`; no root monorepo workspace). Bootstrap `create-expo-app --template blank-typescript` (Expo SDK 54) + the **GreenBidder dep set** (navigation, reanimated 4, async-storage, pager-view, expo-location/secure-store/haptics/blur/linear-gradient/image, lucide) + `@tanstack/react-query` v5 + `expo-font`. **No Tamagui** — theme tokens live in plain `theme/` TS objects. **Navigation = `@react-navigation` (tab + native-stack), not expo-router** (file-based routing fights the deep-module layout; GreenBidder-proven). **Feature/deep-module layout:** `src/theme/`, `src/components/shared/` (motion + Logo), `src/lib/` (api client, mmkv, currency), `src/stores/` (zustand), `src/features/{onboarding,auth,home,catalog,product,cart,checkout,orders,rider}/`, `src/navigation/`. Each feature hidden behind its own entry. |
| 15 | **Rider scope (B4)** | **Same Expo project, role-gated, not mocked.** Root picks shell by session `role` from the login response (login already loads `rider`): Customer = 4-tab bottom shell; Rider = Rider shell (availability toggle, claim list, order detail/items-bought, delivery confirm, earnings/stats). Both share the B2 infra incl. `features/rider` deep module. **All rider endpoints are real** — `/auth/register/rider` (vehicle_type + banking_details) and the `auth:sanctum` rider set (`available-orders`, `claim/{order}`, `active-deliveries`, `items-bought/{order}`, `out-for-delivery/{order}`, `delivered/{order}`, `toggle-availability`, `stats`, `history`) — so no mocks. MOBILE_APP_UX "may be mocked" is superseded. **Rider = lighter polish** (Customer-first priority). Entry: onboarding "I'm a Rider" → rider registration; a `rider` sign-in routes to the Rider shell; a Rider shopping uses a separate Customer account (both shells coexist behind one sign-in). |
| 16 | **i18n & currency (B5)** | **English-only for v1** — no i18n library bundled; scaffolding deferred. One cost-zero concession: hard-coded copy lives in `lib/strings.ts` (constants module), not scattered inline, so a future localization pass is mechanical. **ZAR currency** via `Intl.NumberFormat('en-ZA', { style: 'currency', currency: 'ZAR' })` in `lib/currency.ts` → `formatZar(cents)` (2-dp `R 12,34`); APIs already return ZAR; this is the single formatting seam (price tabs, sale prices, cart totals, min-order nudges). |
| 17 | **Deployment (B6)** | **Prototype-only; deployment out of scope.** Run in **Expo Go on an iPhone** (user's iPhone 17-concurrent device). **No EAS/dev build/Play Store** this phase. iOS-styled (San Francisco) per ADR-0002. — _Revised after B6 originally locked Android-first + EAS dev build._ |
| 17b | **Dep swap for Expo Go (B6 pivot)** | Swap **`react-native-mmkv` → `@react-native-async-storage/async-storage`** (bundled in Expo Go; already in GreenBidder deps) so Expo Go can run the store. Same two call sites: cart draft (Q10/B10) + onboarding gating (Q6). All other deps (Reanimated 4 + worklets, pager-view, gesture-handler, svg, expo-location) are Expo-Go-bundled in SDK 54 and run as-is. |
| 18 | **Testing/QA (B7)** | **`jest-expo` units** for pure logic: cart draft (merge + store-switch revalidation), `formatZar`, pricing rules. No component/snapshot churn. **No Maestro/Detox** (they need a built app binary; a prototype in Expo Go has none). Cross-screen QA = a **manual Expo Go checklist** on the iPhone (critical journey: browse → cart → checkout → order placed) + a rider smoke. Optional (not required): a `node` API-contract sanity check against public endpoints + `?store_id=`. |
| 19 | **Accessibility (B8)** | **Respect the iPhone *Reduce Motion* setting.** `AccessibilityInfo.isReduceMotionEnabled()` read at boot (with `reduceMotionChanged` listener) into a `motionPreferences` store; every motion primitive **snaps to end state** (no animation) when on — entrance, press, scale, hero logo, onboarding parallax, morph-drawer. **≥44pt hit targets** on all tappables (`TactilePressable` floor; compact visuals keep the target via padding + `hitSlop`). **Screen-reader labels:** `accessibilityRole`/`label`/`state` on steppers, CTAs, tab-bar items, toggles, cart badge; prices/status read as plain text. |
| 20 | **F1 Navigation transitions** | **GreenBidder-faithful (verified against its `MainTabs.js`):** `@react-navigation` **native-stack** push/pop + **bottom-tabs** — **no `animation` prop anywhere**, i.e. platform-default slide + the bottom-tabs default cross-fade. Branded feel lives in **per-screen `FadeSlideIn` entrances**, not chrome transitions. Native transitions automatically respect iOS Reduce Motion. *(Flow-choreography addendum; the user asked motion & page transitions be "just like the GreenBidder app".)* |
| 21 | **F2 Order-placed success** | **GreenBidder-style logo win, no confetti.** Native-stack push to an **"Order placed"** screen after checkout submit. Hero-once `AnimatedLogo` win using GreenBidder's **`bouncy`** spring (damping 12 / stiffness 180, its "success — use sparingly" spec) + `durations.hero` 680ms, a **Caveat** "We'll get it to your door" + order # + **`success` haptic** + **"View order" → Order timeline**. Mirrors GREENBIDDER §3 ("reserve hero for order-placed success"); **no `react-native-confetti-cannon`** (stays to the one-new-dependency rule, decision 13). *(Flow-choreography addendum.)* |
| 22 | **F3 Empty states** | **One shared `EmptyState` component** (GreenBidder-faithful, mirroring `SavedListingsScreen`/`SearchScreen`): centered **lucide** glyph (ShoppingCart / Receipt / SearchX / Tag) → **title** (heading, semibold) → **one secondary caption**, centered; **delayed ~200ms rise+scale entrance** (`withDelay(200, withTiming(1, 600, EASE_SETTLE))`, translateY 20→0 + scale 0.95→1), Reduce-Motion-safe. Copy: cart "Your cart is empty / Add a Special or two to get started" + **Browse Specials** CTA · orders "No orders yet / Your delivery timeline will live here" · search "No matches for — / Try a different search" + **category chips** (GB recovery pattern) · Specials "No Specials right now / New deals land every week". No illustration. *(Flow-choreography addendum.)* |
| 23 | **F4 Loading beyond the grid** | **Skeletons where the shelf shape is predictable**: (1) 2-col product grid → `SkeletonCard` (decided); (2) **Specials carousel → a horizontal `SkeletonCard` variant** (same component, orientation prop). Everything else keeps GreenBidder's plain `ActivityIndicator` spinner: Home Store-resolution header, search in-progress row ("Searching…"), **order history list, order detail, account, cart sync**. Spinners for fast auth'd fetches (no skeleton flicker); skeletons reserved for visible network shelves. *(Flow-choreography addendum.)* |
| 24 | **F5 Notification deep-nav** | Each status-change **local** notification carries `data: { orderId }`. One **`lib/notifications.ts` bridge**: subscribes `addNotificationResponseReceivedListener` at boot **and** checks `getLastNotificationResponse()` for **cold-start** taps (app killed). Resolves the route per role — Customer → Orders stack `OrderDetail { orderId, fromNotification: true }`; Rider → rider order detail `{ orderId }` — and navigates via a module-level **navigation ref**. OrderDetail reuses the existing TanStack Query key (`['order', id]`) so a tap never double-fetches. *(Flow-choreography addendum.)* |
| 25 | **F6 Review flow** | **Inline review card in Order detail**, shown when `status === delivered` && no `review` yet (surfaces naturally right after Delivery Confirmation). **5 amber stars** (TactilePressable, `selection` haptic per tap) + optional comment (max 500, enforced) → `POST /orders/{id}/review`. Submit = `commit` haptic; on success the card collapses to "Thanks — your Rider's rating is updated" with `success` haptic. Star-ratings are Checkstar's own rating language (Sneaksy rating amber); GreenBidder's emoji-dimension sheet dropped (no multi-dimension API). *(Flow-choreography addendum.)* |
| 26 | **F7 Cancel flow** | Cancel button on Order detail while `status` ∈ **{pending, confirmed, preparing}** — **not** `out_for_delivery` (Rider already en route; despite the state machine permitting it, the app doesn't surface last-minute cancel — the "it's on its way" trust moment). Tap → **32px confirm sheet**: warning copy ("Cancel this order? Items are released, no charge for COD"), optional **reason chips** ("Changed my mind" / "Found elsewhere" / "Order is late") mapped to the `reason` field, **`warning` haptic**, destructive confirm + dismiss. On success: status → cancelled in place (poll picks it up), glass toast "Order cancelled", reason lands in the **Order Activity Log**. *(Flow-choreography addendum.)* |
| 27 | **F8 Search UX** | Home search bar is a **tappable field → native-stack push to a Search screen** (GreenBidder shape; auto-focus input on mount). TanStack Query live results, **400ms debounce, min 2 chars**, `?search=` **+ `?store_id=`** (chosen delivery Store). Result cards **reuse the product-grid card** (angled image + inline stepper). **IDLE state**: recent searches (**local async-storage, last 5** — no backend `search_history` endpoint exists) + **Browse Categories chips** (from `/categories`). "Searching…" spinner row + result count (GB-faithful). No-results = F3 `EmptyState`. **No "trending"** (no backend signal; Specials fill that role). *(Flow-choreography addendum.)* |
| 28 | **F9 Rider claim-lost** | On a **409** from claim: **glass toast** "Already claimed by another Rider" (**warning** haptic, amber/danger tint) + **drop that Order from the local claim list** and invalidate/refetch `available-orders` (it's likely gone from the next poll anyway). No navigation, no screen — lighter polish, first-claim-wins stays implicit. *(Flow-choreography addendum.)* |
| 29 | **F10 Guest → sign-in** | Guest fills checkout (address + payment method) normally; tapping **Place order** with no session → **native-stack push of the Auth screen** (`intent: 'checkout'`; checkout stays mounted beneath, nothing lost). On auth success: run `/cart/sync` merge immediately → `navigation.goBack()` to checkout → checkout **invalidates/refetches the server cart on focus** (`['cart']`) so the merged authoritative cart shows in place → Place order again → POST. Registration = same Auth screen ("New here? Create account"). *(Flow-choreography addendum.)* |
| 30 | **F11 Session / 401** | Centralized in **`lib/api` client**: on **401** from any authenticated call → clear token + session (secure-store + zustand), glass toast "Session expired — sign in again", navigate to **Auth via navigation ref**; Guest browsing (public endpoints) still works. **Explicit logout** clears token + session only. **Cart draft persists** (local device draft; signing back in reconciles via `/cart/sync` — matches the "persist cart + trust" principle) and **delivery-Store persists** (a browse preference, not account data). *(Flow-choreography addendum.)* |
| 31 | **C. Store seam** | **Verified schema fact:** `store_product` carries **no price** — only `stock_quantity` + `is_available` (migration 095004), so pricing is **product-global** (`PricingService::effectivePrice`: `sale_price` → collection Special → base price). **Decision: the chosen Store is purely an aspirational browse filter** (`?store_id=` on `/products` for availability only, Q9). Order intake stays product-global — no per-Store price exists to diverge; the **Order timeline shows the real fulfilling Store** (`OrderClaim` unconditionally sets `store_id`). Store-switch cart revalidation (Q10) guards checkout-time availability. Zero backend change; option (b) (`?store_id=` on `POST /orders` + `aspirational_store_id` column) is **moot** (no per-Store price to price against) and would fight the loose stock-by-design model. No ADR — do-nothing decision, trivially reversible. *(Flow-choreography addendum.)* |
